# BRAND.md

## Document status

Status: Brand discovery  
Working brand name: Hablyra — preliminary name screening passed; formal trademark clearance still required  
Visual identity direction: calm minimal premium — detailed system still to be designed

This document intentionally does not invent a brand identity before the product owner chooses positioning.

---

## 1. Brand objective

Create an identity that feels intentional, modern and trustworthy while fitting a private behavior-tracking product.

The rebrand should make the app feel like a new product, not a reskinned fork.

---

## 2. Required brand decisions

### Product name
Hablyra — approved working product name, pending formal trademark clearance.

### Tagline
"Break the loop. Build your progress."

### One-sentence promise
"Hablyra helps adults break unwanted behavior loops by making events easy to track and progress easy to understand."

### Brand personality
Approved traits:
- calm
- focused
- non-judgmental
- private
- minimal
- premium

The product should feel serious and polished without becoming clinical or cold.

---

## 3. Emotional direction

The product deals with behavior users may feel uncomfortable about.

Default brand behavior:

- never shame
- never celebrate failure
- never use aggressive guilt
- avoid moral labels such as "good person" / "bad person"
- acknowledge setbacks neutrally
- emphasize continuity and information
- make progress visible without implying perfection

---

## 4. Voice and tone

### Default voice
Clear, concise, human, respectful.

### Microcopy
Prefer:
- short action labels
- concrete verbs
- neutral error messages
- encouraging but factual progress language

Avoid:
- motivational clichés
- excessive exclamation marks
- childish gamification language unless explicitly chosen
- medical promises
- manipulative retention copy

---

## 5. Naming system

Once the new product name is approved, define separately:

- Store display name
- Short brand name
- Legal/company name if applicable
- Android application label
- iOS display name
- Repository/project name
- Internal code prefix if needed
- Domain name
- Support email identity

Do not automatically rename technical identifiers to match the display brand.

---

## 6. Logo and icon requirements

The final visual identity should define:

- master logo
- wordmark if needed
- app launcher icon
- monochrome Android icon
- adaptive icon foreground/background
- iOS icon
- small-size recognizable mark
- store artwork rules

The icon must remain recognizable at small launcher sizes.

Do not rely on small text inside the app icon.

---

## 7. Brand color requirements

Direction: calm, modern and high-contrast.

Avoid the current aggressive red-heavy identity as the dominant brand language.

Recommended visual territory:
- deep neutral backgrounds
- soft light surfaces
- one distinctive cool accent family
- restrained success/progress treatment
- warm destructive/error treatment only where semantically necessary

Exact palette values must be chosen during design-system work after visual exploration.

The palette must define semantic roles rather than only raw colors.

Required roles:

- brand primary
- on-primary
- background
- surface
- elevated surface
- primary text
- secondary text
- outline/divider
- success/progress
- warning
- error/destructive
- disabled states

Colors must meet appropriate contrast requirements for text and controls.

---

## 8. Typography direction

Direction: clean, contemporary, highly legible and numerically strong.

Default recommendation for V1: use a high-quality system/native-friendly sans-serif approach unless a custom font creates a clear brand advantage.

Before introducing a custom font, evaluate:

- license
- Android/iOS availability
- binary size
- readability
- numeric legibility for timers
- localization support
- Compose Multiplatform integration

A system font is acceptable if it produces a stronger product than a decorative custom font.

---

## 9. Brand assets source of truth

When final assets exist, place source/export documentation in a dedicated brand/design asset location.

Codex should not generate random substitute logos, colors or icons during implementation if approved assets are missing.

Use explicit placeholders and surface the missing asset instead.

---

## 10. Old-brand cleanup checklist

Before release, search for:

- "Break Bad Habits"
- "breakbadhabits"
- old icon assets
- old color constants
- old screenshots
- old README/store references
- old accessibility labels
- package names where a change was approved
- Firebase app identity
- analytics event names where relevant
- generated artifact names
- iOS target/display references

Each occurrence must be categorized as:
- user-visible and should change
- technical identity intentionally preserved
- legal attribution that must remain


## 11. Naming clearance requirement

Preliminary exact-name screening for "Hablyra" found no obvious direct match in major app-store/web searches at the time of naming.

Before public release, still perform:
- Google Play name search
- Apple App Store name search
- domain availability check
- EUIPO trademark search
- DPMA trademark search if Germany is a target market
- WIPO Global Brand Database search
- USPTO search if the US is a target market

Codex must not interpret preliminary screening as legal clearance or exclusivity.

## 12. Store positioning

Primary category direction: Health & Fitness.

Store message hierarchy:

1. Track unwanted habits
2. See how long you've stayed on track
3. Log events without judgment
4. Understand patterns through history and insights

Avoid claims about treating addiction, anxiety, depression or other medical/mental-health conditions.
